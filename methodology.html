КАК ЧИТАТЬ ДАННЫЕ AI COUNTDOWN

Как понять, сколько работы уже выполняет AI

Для оценки замещения важно знать, что сделал AI, в какой выборке и сколько работы осталось человеку.

01

Статус текущей версии

Версия 0.2 — прототип с частично подключёнными данными. Кольца показывают три направления наблюдения: Код, Работа и Жизнь. Данные по ним имеют разную природу.

КОД

Сигнал из выборки

Данные об участии AI в публичных репозиториях. Они включают помощь AI и генерацию изменений; для оценки замещения всего процесса нужны дополнительные наблюдения.

РАБОТА

Условные 31%

Значение задано для показа интерфейса. Заявления компаний и опросы собираются отдельно. Сопоставимая доля замещённой работы пока не рассчитана.

ЖИЗНЬ

Условные 24%

Значение задано для показа интерфейса. Для оценки нужны данные о регулярных задачах, принятых результатах и оставшемся участии человека.

02

Что считать замещением работы

Наблюдение должно описывать конкретную задачу: например, обработку однотипных обращений или подготовку документов. Внутри сопоставимой выборки целевая метрика выглядит так:

Замещение = объём ручной работы, выполненной AI / весь сопоставимый объём работы

Единица объёма определяется заранее: однотипные задачи или их трудоёмкость. Вместе с долей нужны период, размер выборки, критерий качества, затраты на проверку и доля возвратов человеку.

Полное замещение задачиAI доводит конкретную задачу до принятого результата. Человек может сохранять постановку целей, контроль и ответственность.

Карта на главной странице описывает степень передачи работы: помощь, выполнение задачи, ведение процесса. Участие AI в развитии моделей рассматривается отдельно. Кольца не определяют текущую ступень для всего общества или расстояние до AGI и ASI.

03

Что означает общее число

Модель= Code × 0.40 + Work × 0.35 + Life × 0.25

Эта формула сохранена как демонстрационная модель интерфейса. Веса выбраны в прототипе и пока не подтверждены сопоставимыми наблюдениями. Часть входных значений условная (Жизнь и одна из оценок Работы), поэтому общий процент не измеряет долю заменённой человеческой работы.

Перед публикацией общего индекса нужны общие правила измерения, обоснование весов и данные по каждому направлению. Пропуск данных должен отображаться как отсутствие оценки.

04

Откуда берётся показатель Кода

Backend берёт медиану только совместимых процентных источников:

Code = median(процент AI по совместимым источникам)

Совместимых источников два. Первый — AI Code Radar с опубликованным weighted AI percentage (34,2% в сохранённом снимке); медиана по репозиториям внутри Radar — 28,5% — сохраняется отдельно как контекст. Второй — собственные исследования AI Countdown: среднее по проанализированным на сайте публичным репозиториям доли изменённых строк, отнесённых AI-агентам. Каждый репозиторий — один голос; учитываются не-форки с хотя бы 20 проанализированными коммитами. Репозитории выбирают посетители, поэтому выборка не случайна.

Slop Score подключён как вспомогательный эвристический источник. Его медиана описывает типичный репозиторный сигнал, а не ту же самую долю AI-кода, поэтому она не включается в медиану процентных источников.

Монитор GitHub AI Contributors показывает, в каких публичных репозиториях участвовали AI-связанные аккаунты и сколько у них commit contributions. Это supporting signal: аккаунт, автор коммита или AI-подпись не доказывают долю AI-кода во всём репозитории.

  • Декларация об участии AI не подтверждает авторство каждой строки.
  • Покрытие показывает, сколько репозиториев включено в расчёт.
  • При добавлении нового источника в медиану попадёт только сопоставимый процент с описанным знаменателем.
  • Рост выпуска кода требует отдельной проверки качества и трудозатрат.

Источники: Slop Score, AI Code Radar и GitHub Contributions API.

05

Откуда берётся показатель Работы

Работа= median(оценка прототипа, оценка профессий)

Работа считается так же, как Код: медиана совместимых процентных источников. Первый источник — прежнее условное значение прототипа (31%). Мы его сохраняем как один из голосов.

Второй источник — собственная оценка профессий AI Countdown. Классификатор — международный ISCO-08: 436 профессиональных групп, на нём построены ESCO в ЕС и ОКЗ в России; каждая профессия имеет постоянный ключ — код ISCO. Частотность берём из ILOSTAT: занятость по 2-значным группам ISCO-08 в США, 32 странах Европы, России и 23 странах Азии (последний доступный год). Данных нет по Китаю, Корее, Казахстану, Малайзии и Узбекистану.

Каждую профессию целиком оценивает языковая модель через OpenRouter по шкале: 0% — нейросеть никак не может помочь, 50% — справляется с помощью человека, 100% — готова выполнять работу без человека. AI здесь — не только программы: он может действовать в физическом мире через антропоморфного робота (две руки, ходьба, инструменты для людей) или дрон-квадрокоптер. Тело оценивается по возможностям сегодняшних роботов и дронов — ловкости, силе, выносливости, надёжности и безопасности рядом с людьми; физическая работа сверх этого остаётся человеку. До версии промпта 2 оценка учитывала только программы. В источник идёт медиана оценок по всем профессиям: каждая профессия — один голос. Средние, взвешенные по занятости, показываем отдельно по США, Европе, России и Азии.

Прогоны воспроизводимы: в файле прогона записаны дата проверки, модель, temperature, seed, допущения о теле AI, текст промпта и его sha256, а также sha256 классификатора. Новые оценки добавляются отдельными файлами в data/work/ratings/; текущим источником становится самый свежий прогон, покрывающий не меньше 90% профессий. Это оценка модели о том, что AI способен делать сейчас, а не наблюдаемое внедрение. Полный список — на странице профессий. Потенциал автоматизации Meo остаётся отдельным наблюдением со своей шкалой.

06

Как читать заявления компаний

Карточки сохраняют исходную единицу измерения и масштаб заявления. Доля кода, доля токенов AI-ответов, использование инструмента и ожидания сотрудников описывают разные наблюдения.

СОЗДАННЫЙ РЕЗУЛЬТАТ

Код и документы

Сколько результата создано AI в обозначенной выборке. Для оценки замещения нужны также данные о проверке, исправлениях и времени человека.

ИСПОЛЬЗОВАНИЕ

Инструменты и привычки

Как часто люди обращаются к AI или каким инструментом пользуются. Чтобы оценить переданную работу, нужно знать, что происходит после обращения.

Например, токены через Codex в отчёте OpenAI характеризуют использование AI-инструмента инженерами. Доля нового кода Google включает проверку инженерами. Опрос AWS о 2028 годе описывает ожидания. Эти числа не усредняются и не меняют условное значение кольца «Работа».

Ссылки на исходные публикации указаны в карточках на главной странице.

07

Задачи, штат и потенциал автоматизации

Для сообщения о сокращении команды долю считаем от указанной численности этой команды:

Доля сокращения = число сокращённых позиций / исходная численность команды
СВЯЗЬ ЗАЯВЛЕНА

Сокращение штата

Если руководитель связывает сокращение с AI, сохраняем эту формулировку как заявление компании. Отдельно указываем команду и период.

ОБЪЁМ РАБОТЫ

Эквивалент сотрудников

Оценка работы AI в эквиваленте полной занятости описывает нагрузку. Для расчёта доли замещения нужны сопоставимые команда, период и единицы.

ПОТЕНЦИАЛ

Автоматизируемость

Meo оценивает потенциальную автоматизацию профессий. Взвешивание по занятости показывает экспозицию выборки, а фактическое замещение требует наблюдений о внедрении.

Для Klarna показываем заявленный объём — более 700 эквивалентов полной занятости. Соотношение с общим штатом из другого контекста убрано: оно не даёт надёжной доли замещённой работы.

08

Даты, доступность и ограничения

На главной странице показываются источник и статус снимка Кода. Сохранённые данные позволяют открыть последний доступный результат при недоступности внешнего источника.

  • Снимок источника — полученные данные; статус сам по себе не означает непрерывного измерения.
  • Устаревший снимок — дата источника старше 45 дней.
  • Сохранённые данные — последний доступный результат, используемый после ошибки обновления.
  • Опрос разработчиков характеризует участников опроса, а не всё население.
  • Открытые репозитории не охватывают весь код, а заявления компаний могут быть выборочными.

Для новых наблюдений фиксируем источник, период, выборку, единицу измерения, степень участия человека и ограничения. Направление «AI создаёт AI» пока показывается без числовой оценки.

09

Реестр найденных источников

В объединённый backend-снимок входят live feeds, сохранённые результаты, ручные наблюдения и источники для cross-check. Роль каждого источника фиксируется отдельно:

  • Slop Score — эвристический индекс репозиториев.
  • AI Code Radar и AI Attestation — AI-attestation и основной сопоставимый процент Code.
  • Bot Commits и github_explosion — публичные AI-атрибутированные коммиты и временные ряды.
  • OSSInsight и Public API — независимая аналитика публичной GitHub-активности.
  • GitHub AI Contributors — нижняя граница репозиториев и коммитов AI-связанных аккаунтов.
  • qmmit, Causari Survival, AI Agent Adoption и Git AI / Grafana — supporting signals по автономности, выжившим строкам, adoption и telemetry.
  • Anthropic Economic Index, Stack Overflow Survey 2026 и Meo Workforce Data — Work, Life, survey и occupational exposure.
  • Отчёты OpenAI, Anthropic, xAI, Google, Microsoft и AWS / Amazon — reported company signals.
  • Salesforce, Klarna и Amazon workforce — наблюдения по объёму работы и сокращениям.

Полный реестр, статусы и машинный snapshot сохранены в README.md, data/sources.json и combined-snapshot-cache.json.

READING AI COUNTDOWN DATA

How to assess the work AI already performs

An estimate of replacement needs to establish what AI did, in which sample, and how much human work remains.

01

Status of this version

Version 0.2 is a prototype with partial data. The rings cover Code, Work, and Life, with different kinds of evidence in each area.

CODE

A sample signal

AI involvement in public repositories, including assistance and generated changes. Assessing replacement of the full workflow needs additional evidence.

WORK

Illustrative 31%

A value chosen to demonstrate the interface. Company reports and surveys are collected separately. A comparable replacement share has not been calculated.

LIFE

Illustrative 24%

A value chosen to demonstrate the interface. An estimate needs evidence about recurring tasks, accepted results, and remaining human involvement.

02

What counts as replaced work

An observation should describe a specific task, such as handling comparable support requests or preparing documents. Within a comparable sample, the target metric is:

Replacement = manual work volume performed by AI / total comparable work volume

Define the unit in advance: similar tasks or their labor requirements. Report the period, sample size, quality criteria, review effort, and the share handed back to people alongside the estimate.

A fully replaced taskAI completes a specific task through to an accepted result. A person may retain goals, oversight, and accountability.

The map on the main page describes assistance, task execution, and workflow execution. AI involvement in model development is considered separately. The rings do not assign a current stage to society or a distance to AGI and ASI.

03

What the overall number means

Model= Code × 0.40 + Work × 0.35 + Life × 0.25

This formula is retained as an interface demonstration. The weights are prototype choices and have not been validated against comparable observations. Some inputs are illustrative (Life and one of the Work sources), so the overall percentage does not measure the share of human work replaced.

A public overall index requires consistent measurement rules, justified weights, and evidence in every area. Missing data should appear as an unavailable estimate.

04

Where the Code value comes from

The backend takes the median of compatible percentage sources only:

Code = median(AI percentage across compatible sources)

There are two compatible sources. The first is AI Code Radar with its published weighted AI percentage (34.2% in the saved snapshot); Radar’s repository median — 28.5% — is retained as context. The second is AI Countdown’s own research: the mean share of changed lines attributed to AI agents across public repositories analyzed on this site. Each repository is one vote; only non-fork repositories with at least 20 analyzed commits are included. Visitors choose the repositories, so the sample is not random.

Slop Score is integrated as a separate heuristic signal. Its median describes a typical repository signal, not the same AI-code percentage, so it is excluded from the percentage-source median.

The GitHub AI Contributors monitor shows which public repositories received contributions from AI-linked accounts and how many commit contributions they made. This is a supporting signal: an account, commit author, or AI signature does not prove the AI share of the whole repository.

  • An AI involvement declaration does not establish authorship of every line.
  • Coverage shows how many repositories entered the calculation.
  • A new source enters the median only when it publishes a comparable percentage with a defined denominator.
  • Growth in code output requires separate checks of quality and human effort.

Sources: Slop Score, AI Code Radar, and GitHub Contributions API.

05

Where the Work value comes from

Work= median(prototype estimate, occupation ratings)

Work follows the same rule as Code: the median of compatible percentage sources. The first source is the earlier illustrative prototype value (31%), kept as one vote.

The second source is AI Countdown's own occupation rating. The classifier is the international ISCO-08: 436 unit groups that ESCO in the EU and OKZ in Russia are built on; each occupation has a permanent key, its ISCO code. Frequency comes from ILOSTAT: employment by ISCO-08 sub-major group in the United States, 32 European countries, Russia, and 23 Asian countries (latest available year). There is no data for China, Korea, Kazakhstan, Malaysia, or Uzbekistan.

A language model rates each occupation as a whole through OpenRouter: 0% means AI cannot help at all, 50% means AI handles the job with a person, 100% means AI is ready to do it without a person. AI here is more than software: it can act in the physical world through a humanoid robot (two arms, walking, tools made for people) or a quadcopter drone. The body is judged by what today’s robots and drones can do — dexterity, strength, endurance, reliability, and safety around people; physical work beyond that stays with people. Before prompt version 2 the rating counted software only. The source value is the median rating across all occupations, one vote per occupation. Employment-weighted means are shown separately for the US, Europe, Russia, and Asia.

Runs are reproducible: each run file records the check date, model, temperature, seed, the assumptions about the AI’s body, the prompt text and its sha256, and the classifier sha256. New ratings are added as separate files in data/work/ratings/; the newest run covering at least 90% of occupations becomes the current source. These are model judgements of what AI can do now, not observed adoption. The full list is on the occupations page. Meo automation exposure remains a separate observation with its own scale.

06

Reading company reports

Cards retain the original measurement unit and the scope of each claim. Code share, AI output token share, tool usage, and employee expectations describe different observations.

OUTPUT

Code and documents

The result produced by AI in a defined sample. Assessing replacement also needs evidence about review, corrections, and human time.

USAGE

Tools and habits

How often people use AI or which tool they choose. Assessing the work handed over requires evidence of what happens after the request.

For example, Codex tokens in OpenAI’s report describe engineers’ use of an AI tool. Google’s new code share includes engineer review. The AWS survey about 2028 records expectations. These values are not averaged and do not change the illustrative Work value.

Original publications are linked from cards on the main page.

07

Tasks, staffing, and automation potential

For a reported team reduction, calculate the share against the stated initial size of that team:

Reduction share = positions removed / initial team headcount
STATED CONNECTION

Staff reductions

If a leader attributes a reduction to AI, preserve that wording as a company claim. State the team and period separately.

WORK VOLUME

Employee equivalents

AI work in full-time employee equivalents describes workload. A replacement share needs a comparable team, period, and unit.

POTENTIAL

Automation exposure

Meo estimates potential occupation automation. Employment weighting gives exposure for the sample; actual replacement requires evidence of deployment.

The Klarna card shows reported work volume: over 700 full-time equivalents. Its ratio to company headcount from another context has been removed because it does not establish a reliable replacement share.

08

Dates, availability, and limitations

The main page displays the Code source and snapshot status. Stored data makes the last available result accessible when an external source is unavailable.

  • Source snapshot means received data; the status alone does not imply continuous measurement.
  • Outdated snapshot means the source date is over 45 days old.
  • Saved data is the last available result used after an update error.
  • A developer survey describes its respondents rather than the whole population.
  • Public repositories do not cover all code, and company disclosures may be selective.

For new observations, record the source, period, sample, unit, human involvement, and limitations. The AI building AI area currently has no numerical estimate.

09

Source registry

The combined backend snapshot includes live feeds, saved results, editorial observations, and cross-check sources. Each source keeps its own role:

  • Slop Score — repository heuristic index.
  • AI Code Radar and AI Attestation — AI attestation and the primary comparable Code percentage.
  • Bot Commits and github_explosion — public AI-attributed commits and time series.
  • OSSInsight and its Public API — independent public GitHub activity analytics.
  • GitHub AI Contributors — lower bound for repositories and commits involving AI-linked accounts.
  • qmmit, Causari Survival, AI Agent Adoption, and Git AI / Grafana — supporting signals for autonomy, surviving lines, adoption, and telemetry.
  • Anthropic Economic Index, Stack Overflow Survey 2026, and Meo Workforce Data — Work, Life, survey, and occupational exposure signals.
  • Reports from OpenAI, Anthropic, xAI, Google, Microsoft, and AWS / Amazon — reported company signals.
  • Salesforce, Klarna, and Amazon workforce — work-volume and headcount observations.

The full registry, statuses, and machine-readable snapshot are saved in README.md, data/sources.json, and combined-snapshot-cache.json.
