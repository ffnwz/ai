# AI Countdown

AI Countdown — открытый исследовательский прототип о том, какую часть жизни уже занимает AI.

[English version](README.md) · Русская версия

Сайт: [ai.ffnwz.lat](https://ai.ffnwz.lat)

## Что измеряет проект

На главной странице есть три направления:

- **Code** — участие AI-агентов в публичной разработке;
- **Work** — рабочие задачи и процессы;
- **Life** — повседневные задачи.

Это не точный мировой процент замещения. Источники имеют разные знаменатели, периоды и уровень доказательности, поэтому каждый сигнал хранится отдельно.

## Архитектура

- `server.js` — Node.js backend, API, кэширование и фоновые анализы;
- `app.js` — интерфейс, локализация, анимации и экспорт карточек;
- `data/` — редакционные источники, классификаторы, реестр бытовых задач, model-runs и локальные данные;
- runtime-состояние (анализы репозиториев, профили контрибьюторов, ряд метрик, кэши источников, обход Slop Score и блокировки) хранится в MongoDB через `storage.js`; пока Mongo доступна, в `data/` ничего не пишется. Без Mongo (или с `AI_COUNTDOWN_MONGO=false`) то же состояние пишется в JSON-файлы в `data/`, а существующие JSON-файлы один раз импортируются в пустые коллекции;
- HTTP-сервер отдаёт только белый список публичных страниц, скриптов, картинок и закоммиченных справочных данных; `.env`, код сервера, скрипты и runtime-данные не отдаются;
- ошибки API содержат стабильный `code` (`invalid-request`, `github-rate-limit`, `storage-unavailable`, `internal-error`, …) и безопасный текст; у внутренних сбоев есть `incidentId`, по которому ошибка ищется в логе сервера;
- GitHub API используется только на backend, токен никогда не передаётся в браузер.

## Анализ репозитория

Пользователь может отправить публичный GitHub-репозиторий. Backend:

1. сохраняет репозиторий и историю замеров;
2. анализирует до 300 коммитов в первом ответе;
3. продолжает остальную публичную историю в фоне;
4. распознаёт AI-агентов по публичным аккаунтам, email, `Co-Authored-By` и подписям, которые агенты пишут в тело коммита («Generated with Claude Code», `Amp-Thread`); название продукта в заголовке коммита не считается авторством;
5. относит ботов зависимостей, релизов, переводов и CI (Dependabot, Renovate, GitHub Actions, Weblate и любой другой `[bot]`, кроме известных AI-агентов) к **автоматизации**: это не работа человека и не код, написанный AI, поэтому доли AI считаются только по строкам AI + человека;
6. показывает вклад агентов и остальных контрибьюторов по изменённым строкам (истории длиннее 5 000 коммитов анализируются за последние 12 месяцев; один анализ хранит не больше 8 000 самых новых коммитов);
7. повторно использует кэш не чаще одного анализа в сутки.

Для индекса Кода доля AI в каждом репозитории считается по коммитам за последние 12 месяцев, если их не меньше 20 (люди + AI). Кроме репозиториев посетителей, сервер в фоне анализирует эталонный набор [`data/reference-repositories.json`](data/reference-repositories.json) (46 широко используемых проектов разных экосистем) и обновляет его раз в неделю, без рекурсивного обхода профилей. Эвристика репозиториев автора — только сигнал профиля: она показывает вероятного агента контрибьютора, но не переносит его коммиты на агента. Доли учитывают только коммиты с публичной AI-меткой, поэтому это нижняя граница.

Аккаунты агентов, точные адреса агентов, подписи в теле коммита и список автоматизации лежат в [`data/ai-agents.json`](data/ai-agents.json). Технический коммиттер GitHub `web-flow` (слияния через веб-интерфейс) никогда не считается автором. При изменении правил повышается версия классификации: анализы, где сохранена классификация каждого коммита, пересчитываются при старте сервера, более старые — при следующем анализе.

Если агент указан в `Co-Authored-By`, весь коммит относится к агенту, потому что GitHub не даёт разбивку строк между соавторами. Для человека такой коммит запускает временную последовательность: последующие коммиты без агента продолжают относиться к этому агенту, пока человек не сделает коммиты без агента в три разных дня. После этого следующий коммит считается собственным. Коммит с другим распознанным агентом сразу переключает активного агента. По мере догрузки полной истории последовательность пересчитывается в хронологическом порядке.

Профиль контрибьютора проверяет до 30 собственных публичных не-форков, отсортированных по дате последнего обновления. Найденные репозитории дедуплицируются и ставятся в один ограниченный фоновый рекурсивный проход; дочерние анализы не запускают новый обход. Так расширяется датасет без бесконечного каскада запросов.

### Top 3 repositories

Топ-3 сортируется по взвешенному баллу:

```text
leaderboard score = AI changed lines × min(1, total changed lines / 10,000)
```

`Total changed lines` — additions плюс deletions в обработанной истории. Это не количество уникальных строк, оставшихся в текущем HEAD. Поправка не даёт небольшому репозиторию с 100% AI-вкладом автоматически обойти крупный проект.

## API

- `GET /api/combined-snapshot` — объединённый снимок для главного индекса;
- `GET /last.json` — компактный публичный JSON со значениями Code, Work, Life, Overall, отдельным `selfBuild` и датами обновления;
- `GET /api/metric-series` — временной ряд Code, Work, Life, Overall и `selfBuild`;
- `GET /api/self-building` — показатель «AI создаёт AI», материалы, исключения, методология и история замеров;
- `GET /api/repository-analyses` — сохранённые анализы и Top 3;
- `GET /api/repository-analysis?repo=...` — анализ публичного репозитория;
- `POST /api/repository-analysis` — запуск анализа;
- `POST /api/contributor-analysis` — анализ собственных репозиториев контрибьютора;
- `GET /api/source-feeds` — внешние источники и их freshness.
- `GET /api/life-index` — показатель Life и медиана совместимых источников;
- `GET /api/life-tasks` — датасет бытовых задач, частотность и оценки модели.

```powershell
npm start
```

После запуска откройте `http://127.0.0.1:8765/`.

## Фронтенд на GitHub Pages

Статический фронтенд публикуется workflow-файлом `.github/workflows/deploy-pages.yml`. На GitHub Pages запросы браузера идут в `https://ai.ffnwz.lat`; GitHub-токены и доступ к базе остаются только на backend.

Создайте `.env` на основе `.env.example` и добавьте локальный fine-grained GitHub-токен. Имя переменной и значение не публикуйте:

```env

```

Нужен fine-grained token с минимальными правами. Секреты, `.env`, локальные кэши, lock-файлы и `deploy.local.md` не должны попадать в Git.

## Датасет «AI создаёт AI»

`data/self-building-observations.json` ведётся отдельно от общих редакционных наблюдений. В нём сохраняются материалы каждой компании, сопоставимое значение, дата и область заявления, исключения и история замеров.

Текущее значение — медиана сопоставимых публичных заявлений о коде, написанном AI внутри собственной инженерной разработки AI-компаний:

```text
selfBuild = median(Anthropic 80%, Google 75%, середина диапазона Microsoft 25%) = 75%
```

99% OpenAI по AI-выходным токенам остаётся в материалах, но исключается из медианы: это доля токенов, а не доля всего кода. xAI отмечен как источник без сопоставимого процента. Показатель не утверждает, что модели самостоятельно улучшают себя: постановка задачи, проверка, исправления и выпуск человеком в это число не входят. Каждый обновлённый снимок записывает `selfBuild` в `data/metric-series.json` или коллекцию Mongo `ai_countdown_metric_series`.

## Датасет бытовых задач и методология Life

`data/life/life-tasks.json` — редактируемый реестр повторяющейся домашней и личной организационной работы. В нём есть ежедневные, еженедельные, ежемесячные и сезонные дела, число повторений в год, ориентировочные минуты и программные, умные домашние или роботизированные механизмы, которые могут выполнить часть процесса. Список сделан явным, чтобы предлагать новые задачи и исправления с подтверждающими данными.

Life показывает долю домашнего времени, которую может взять на себя AI:

```text
годовая нагрузка = повторения в год × типичные минуты × householdShare
наблюдение Life = взвешенное среднее оценок задач, вес — годовая нагрузка
индекс Life = медиана(прототипная оценка, наблюдение задач Life)
```

`householdShare` — доля домохозяйств, где задача вообще есть (выгул собаки — только там, где есть собака); меньше 1 он только у задач, зависящих от питомца или прибора, и это редакционная оценка. Взвешенная медиана сохраняется справочно: когда одна задача занимает пятую часть всех минут, медиана почти не двигается.

Модель оценивает всю задачу: подготовку, загрузку, выгрузку, контроль качества, исключения и раскладывание вещей. Посудомойка или робот-пылесос учитываются только за выполненную ими часть. `refresh-life-tasks.js` оценивает каждую задачу в три прохода с seed 42, 43, 44 и сохраняет медиану по задаче вместе с оценками всех проходов и разбросом в возобновляемых прогонах с hash датасета в `data/life/ratings/`. Hash считается только по полям, которые видит модель. Прогон становится текущим после покрытия не менее 90% списка.

## Датасет профессий и методология Work

В `data/work/` лежат единый классификатор (`isco08-occupations.json`: 436 профессиональных групп ISCO-08 с ключом-кодом, названия EN/RU), занятость ILOSTAT по 2-значным группам для США, Европы, России и Азии (`employment-ilostat.json`), занятость внутри групп по США (`isco08-unit-shares.json`: BLS OEWS, переведённая SOC 2018 → SOC 2010 → ISCO-08 через таблицы O*NET и IBS) и по файлу на каждый прогон оценки в `ratings/`.

```text
оценка профессии = медиана 3 проходов модели (seed 42, 43, 44)
наблюдение профессий = медиана оценок по профессиям (каждая — один голос)
индекс Work = медиана(прототипная оценка, наблюдение профессий)
```

Модель считает программы вместе с антропоморфным роботом или дроном-квадрокоптером, с возможностями сегодняшнего дня. Профессии упорядочены по занятости их 2-значной группы во всех регионах, а внутри группы — по реальной занятости в США; средние, взвешенные по занятости, показываются по регионам. `node refresh-work-occupations.js inputs|shares|rate|verify` пересобирает входные данные, запускает оценку и проверяет файлы прогонов; `verify` проверяет и то, что каждая сохранённая оценка — медиана её проходов.

Код — медиана четырёх совместимых процентных источников: AI Code Radar, наших анализов репозиториев (последние 12 месяцев, только публичные AI-метки, нижняя граница), опроса разработчиков [Sonar State of Code 2026](https://www.sonarsource.com/blog/state-of-code-developer-survey-report-the-current-reality-of-ai-coding/) (по самооценке AI пишет 42% закоммиченного кода) и исследования с детектором AI-кода [Daniotti et al. Если нашли новый публичный источник, датасет, заявление компании или воспроизводимую методику — предложите его в [репозитории на GitHub](https://github.com/ffnwz/ai). ## Ограничения

Code измеряет публичный сигнал участия AI, а не весь мировой код. Work и оценки бытовых задач Life — это суждения модели о возможностях, а не наблюдаемое внедрение. Statements компаний, surveys, occupational exposure и AI-authorship не складываются в один процент без общей единицы измерения.

Проект предназначен для прозрачного наблюдения за источниками и ограничениями, а не для атрибуции авторства каждой строки или доказательства AGI/ASI.

## Как предложить улучшение

Проект открыт для предложений, основанных на проверяемых данных. В публичном [репозитории на GitHub](https://github.com/ffnwz/ai) можно предложить:

- изменения или уточнения методологии;
- новые открытые источники и датасеты;
- исправления значений, дат и происхождения данных;
- воспроизводимые улучшения анализа репозиториев.

Пожалуйста, добавляйте ссылку на подтверждающий материал и указывайте знаменатель, период и единицу измерения. Для обсуждения создайте issue, а готовое изменение оформите pull request.
